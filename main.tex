\begin{abstract}
We specify how a MAMUT-routing benchmark revision assigns numerical meaning to an instance, a route and its reported cost. The instance manifest binds the source artifacts by hash. A reader can load the published arc data or reproduce them with pinned code and compare their complete binary64 digest. Once these operands are fixed, both readers can evaluate the submitted routes exactly. Static benchmarks use a cost matrix. Time-dependent benchmarks use arrival-time functions and optimize the departure of each route. Both settings compare incumbents using the exact objective and derive display values from it. We give the shared contracts, the evaluation rules specific to each setting and worked examples of their consequences.
\end{abstract}
