\section{Identify and materialize the instance}\label{sec:materialization}
The instance manifest names the benchmark family and revision, problem, units, objective and default profile. It identifies the instance descriptor and each required sidecar by path and SHA-256. Resolve family-relative paths from the family collection root. The descriptor binds the depot and customer indexing, demands, capacity, fleet limit, and the declared service, time-window and horizon data. A result identifies its manifest by the SHA-256 of its complete UTF-8 file bytes.

A family may embed the numerical data, distribute a sidecar, or regenerate them from pinned inputs. Preserve the generation code and identify its immutable revision, entry point, parameters (including seeds or simplification tolerances where applicable), input hashes and relevant software environment. For example, a static family can derive distances from a road graph and a TD family can derive ATFs from a road graph and a traffic overlay. Generation ends at the published matrix entries or knot coordinates. The checker interprets those values as binary64 even when the generator rounded them to a fixed number of decimal places.

A source hash identifies the artifact that was read. A separate semantic digest identifies the complete interpreted matrix or directed ATF collection, using the encoding in Appendix~\ref{app:materialization-format}. A regenerated object and the corresponding JSON artifact must yield the same semantic digest. Changing whitespace can change a JSON file hash while preserving its semantic digest. Verification of a complete digest may be streamed or reused while all its dependencies are unchanged. Generating only the arcs visited by a route establishes equality of the full object only if a complete verification for those inputs is already available.
