\section{Evaluate the routes}\label{sec:td-core}
A route is a nonempty sequence of customer indices with implicit depot endpoints. Vertex 0 is the depot and customers are numbered from 1 to $n$. Visit each customer exactly once across the solution. The demand of each route must fit one vehicle, and the number of routes must fit the fleet limit when supplied. Depot demand and service are zero. With no customers, the empty solution has cost zero. Validate instance domains and dimensions before accepting a solution. An invalid instance, an infeasible route and a checker resource failure are distinct outcomes. Only a feasible solution receives an authoritative cost.

\subsection{A common schedule}
Let $d$ be the departure from vertex $i$. On a static arc $(i,j)$ with travel time $c_{ij}$ the arrival is $u=d+c_{ij}$. On a TD arc it is $u=\alpha_{ij}(d)$. With a customer service-start window $[e_j,l_j]$, start service at $b=\max(u,e_j)$ and require $b\leq l_j$. The next departure is $b+s_j$, where $s_j$ is the customer's service duration. Without a window, service begins on arrival. At the depot enforce its opening time on departure and its closing time on return when specified. Arc costs, temporal quantities and the fixed charge are nonnegative, and all windows have ordered endpoints. Each test and arithmetic operation uses the exact interpreted operands.

For a static instance, the matrix covers all ordered pairs and has zero diagonal. In static routing with time windows its arc cost is also its travel time. Starting at depot opening and applying the recurrence gives the earliest schedule. Waiting and service affect feasibility. The static objective sums travel costs on all traversed arcs, including both depot legs.

For a TD instance each ATF covers the common closed departure horizon $[h_0,h_1]$. Its knots $(x,y)$ have nondecreasing abscissas and ordinates, and $y\geq x$. These conditions give nonnegative travel time and First-In, First-Out (FIFO) arrivals. At a repeated abscissa $x$, the arrival at $x$ is its first ordinate $y^-(x)$. Between consecutive distinct abscissas $x<x'$, interpolate from the last ordinate $y^+(x)$ to the first ordinate $y^-(x')$:
\[
 \alpha_{ij}(d)=y^+(x)+\frac{d-x}{x'-x}\bigl(y^-(x')-y^+(x)\bigr),\qquad x<d<x'.
\]
Every arc departure must lie in the horizon. The final arrival may exceed $h_1$ if the depot deadline permits it. For each feasible initial depot departure $t$ in the continuous horizon and depot window, let $a(t)$ be the return time given by the recurrence. FIFO makes this the earliest return at that departure. Minimize the elapsed duration $a(t)-t$ and select the \emph{earliest} departure attaining the minimum. An empty feasible set makes the route infeasible. Appendix~\ref{app:td-attainment} shows that otherwise both values exist and are rational.

\paragraph{The same route under both objectives.}
Suppose both depot legs take 2, customer service takes 2 and must start in $[7,9]$, and the depot window is $[0,15]$. Leaving at 0, the vehicle reaches the customer at 2, waits until 7 and returns at 11. The static travel cost is 4. Under the TD duration objective every departure in $[5,7]$ gives the minimum duration 6, so the stored witness is departure 5. A depot deadline of 10 makes the route infeasible under both profiles.

\subsection{Objective and backend}
For \id{MonoCost}, sum the static route costs. For \id{HierarchicalVehicleCost}, minimize the pair (number of vehicles, total travel cost) lexicographically. For \id{Duration}, sum the TD route minima. For \id{FleetCostDuration}, add the declared fixed charge per vehicle times the number of routes to that sum.

The v0.13 default backend for \id{binary64-exact-v1} uses prepared C++ dyadic arithmetic. The default for \id{td-binary64-exact-v1} uses C++ prefix composition with the GNU Multiple Precision Arithmetic Library (GMP). Python \id{Fraction} is a selectable reference backend for either profile. Backend selection preserves every verdict, exact cost and TD witness. An implementation that exhausts its arithmetic range must promote to exact arithmetic of sufficient width or report a failure.
