\section{Canonical byte streams for materialized arc data}\label{app:materialization-format}

Two implementations can compare the inputs to their checkers by computing SHA-256 over the complete materialized matrix or collection of Arrival Time Functions (ATFs). The manifest records the digest as 64 lowercase hexadecimal digits in \id{materialization.matrix_sha256} for a static matrix or \id{materialization.atf_stream_sha256} for TD arc data. The instance and manifest hashes identify the remaining data, including units, service durations, windows and vehicle charges. In a published TD descriptor, \id{td.atf_sha256} identifies the canonical ATF sidecar JSON, including its metadata. A verifier checks each digest against the byte stream named by its field.

\paragraph{Byte conventions.}
Concatenate the fields in the order given below. Every text field is ASCII. Each line ends with a single LF byte (hexadecimal \id{0a}). Write each structural integer in base 10, using digits 0 through 9, with a single digit for zero and no leading zeros otherwise. Write each numerical operand as exactly 8 bytes, most significant byte first, containing its IEEE~754 binary64 representation after the instance's binary64 reading. Both signed zeros encode as 8 zero bytes. Preserve every other finite value, including subnormals. Reject nonfinite operands. Text and binary fields meet directly, without padding, extra separators or a trailing file marker. Hash the bytes themselves. Hexadecimal text in the companion vectors is a printable representation of those bytes.

\paragraph{Static matrix (\id{MAMUT-MATRIX-v1}).}
Let $N=n+1$ be the number of vertices including depot~0. Write three lines containing \id{MAMUT-MATRIX-v1}, \id{binary64} and $N$, respectively. Write all $N^2$ binary64 entries, including the diagonal, in increasing row index $i=0,\ldots,N-1$ and, within each row, increasing column index $j=0,\ldots,N-1$. Entry $(i,j)$ is the cost from $i$ to $j$. A depot-only instance contributes its single zero diagonal entry.

\paragraph{Directed ATFs (\id{MAMUT-ATF-v1}).}
Write three lines containing \id{MAMUT-ATF-v1}, \id{binary64} and $N$, respectively. Write the 2 binary64 endpoints $h_0,h_1$ of the common departure horizon, in that order. Next write exactly $N(N-1)$ directed arc records in lexicographic order of the integer pair $(i,j)$, with $0\leq i,j<N$ and $i\ne j$. Each ordered pair occurs once. For $N=1$, the stream ends immediately after $h_1$.

Each arc record starts with one ASCII line containing $i$, a comma, $j$, a comma and the number $K$ of materialized knots. For example, \id{0,1,6} followed by LF introduces 6 knots on the arc from the depot to vertex~1. Write $K$ pairs of binary64 operands $(x_k,y_k)$, alternating abscissa and ordinate for each knot in stored order. The first abscissa is $h_0$ and the last is $h_1$. Each ordinate is the absolute arrival time. Include every materialized knot, including collinear knots, identical consecutive pairs and repeated abscissas at either horizon endpoint. At a repeated abscissa the first ordinate is attained and the last supplies the right-hand limit when a following piece exists (Section~\ref{sec:td-core}). Removing such knots or simplifying the sequence changes the encoded operands. Reject missing, duplicate or self arcs and invalid knot sequences before accepting a digest.

\paragraph{Conformance vectors.}
The companion file \id{materialization-vectors.json} supplies the complete byte stream in hexadecimal and its expected digest for each input. The 3-vertex matrix from \id{example-instance.json} occupies 99 bytes. The TD vector \id{directed-jumps} occupies 180 bytes and covers both directions over $[0,2]$. The outward arc has repeated abscissas at 0, 1 and 2. The return arc begins with the smallest positive binary64 subnormal, $2^{-1074}$, as its arrival ordinate. The \id{depot-only} vector has a 40-byte stream consisting solely of the header and the horizon $[0,4]$.
